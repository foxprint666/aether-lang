# Agent Adapters

This directory contains benchmark-side adapters that produce Aether patch JSON.

Implemented now:

- `replay_agent.py`: deterministic adapter that reads a task descriptor and emits the manifest patch with replay-agent metadata.
- `command_agent.py`: command-backed adapter for live/provider integrations, including retry and usage metadata ingestion.
- `mock_provider.py`: local provider-shaped command for testing `command_agent.py` without network or credentials.
- `openai_provider.py`: OpenAI Responses API provider command. Requires `OPENAI_API_KEY` and `AETHER_OPENAI_MODEL`.
- `gemini_provider.py`: Gemini `generateContent` provider command. Requires `GEMINI_API_KEY` and `AETHER_GEMINI_MODEL`.
- `openrouter_provider.py`: OpenRouter chat-completions provider command. Requires `OPENROUTER_API_KEY` and `AETHER_OPENROUTER_MODEL`.
- `subagent_provider.py`: local Codex subagent-simulated provider output for fallback evidence when external free API auth/quota blocks live runs. It is not external provider telemetry.
- `parallel_subagent_provider.py`: replays stored patches generated by independent Codex subagents for repeatable local A/B evidence. It is agent evidence, not external provider token telemetry.

The replay adapter is intentionally not an LLM. It exercises agent patch ingestion, metadata capture, validation, and application without adding provider cost, network dependency, or stochastic behavior.

The mock and local subagent adapters may emit provider-shaped envelopes, but proof scoring excludes their token fields from live-token confidence. Use live Gemini/OpenRouter/OpenAI adapters for token/cost evidence.

Future adapters should allow a benchmark to inspect a repository, receive a task, produce or ingest a patch, submit it to Aether or a control path, and record retries and usage metadata.

Do not couple the benchmark core to one LLM provider.
