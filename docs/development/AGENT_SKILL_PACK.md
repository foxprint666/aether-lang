# Aether as an Agent Skill

Aether should be easy for an LLM agent to use without being trained into the
model. The practical packaging is a skill pack: short instructions, examples,
schemas, and command recipes that any agent wrapper can inject into context.

## Why This Matters

Most coding agents know how to write code, but they often write too much. A
skill pack changes the default behavior:

```text
raw source generation -> structured patch intent
direct write -> validate/snapshot/apply/rollback
ambiguous prose -> schema-checked operation
```

This is the operating-layer view of Aether. The agent remains the reasoning
engine. Aether becomes the code-state control layer.

It contains:

- `decision_policy.md` for dynamic method selection;
- JSON patch examples;
- a short model prompt block;
- Healing Agent verify-gate config example.

## How Models Should Use It

When editing an existing codebase, the model should first decide whether a
structured patch is smaller than a raw rewrite. A simple threshold is:

```text
estimated_patch_tokens <= estimated_full_rewrite_tokens * 0.8
```

If true, the model emits patch JSON. If the change is safety-sensitive, the host
uses full Aether orchestration. If the change is tiny and low-risk, raw editing
may be cheaper.

## Evidence

The latest from-scratch Python module benchmark supports the usability thesis:

```text
Same final project quality
Same accuracy: 0.7361
Same recall: 1.0
Generated token savings: 87.751581%
Generated byte savings: 91.404559%
Build-time savings: 46.044007%
Verify-time savings: -7.649877%
```

This means an agent can describe the desired software state with far fewer
tokens while Aether still produces the same working module.

## Agent CLI

The Python SDK exposes a small CLI wrapper around `PatchOrchestrator`:

```bash
aether validate patch.json
aether apply patch.json
aether rollback <snapshot-id>
```

This makes the skill pack immediately actionable for Codex, Claude Code,
OpenRouter agents, local Ollama agents, and self-healing systems. The remaining
packaging work is publishing/releasing the distribution and collecting larger
live-agent benchmark runs.
