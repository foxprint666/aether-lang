# 🛠️ Contributing Benchmarks

## 📝 Add a Benchmark Task

1. Add or update a task manifest under `benchmarks/tasks/`.
2. Give every task a stable `task_id`.
3. Include language, repository, setup command if needed, test command, timeout, and expected behavior.
4. Use temp or isolated working directories.
5. Record raw results through `benchmarks/run.py` or a runner module called by it.

> [!WARNING]
> Do not commit hand-written result files as evidence.

## 🔌 Add a Language Adapter

Adapters should expose the following conceptual operations:
- `parse`
- `validate`
- `transform`
- `serialize`
- `diagnostics`
- `test_command`

Use the Python LibCST and Node Recast implementations as the first reference points. Keep language-specific behavior out of benchmark core.

```python
# Example Adapter Operations
class LanguageAdapter:
    def parse(self, code: str) -> AST:
        pass
        
    def transform(self, ast: AST, patch: Patch) -> AST:
        pass
```

## 💥 Add a Failure Injection Case

Each failure case should record the following data:

| Field | Description |
|---|---|
| `failure type` | The category of injected failure |
| `failure detected` | Whether the system correctly caught it |
| `rollback triggered` | Whether a rollback was initiated |
| `rollback succeeded` | Whether the rollback successfully reverted state |
| `repository state before` | Snapshot before failure injection |
| `repository state after` | Final state post-rollback attempt |
| `recovery time` | Time taken to recover (when measured) |

Covered failure classes must be documented. Uncovered classes should be listed as limitations.

## 🌍 Add a Real Repository Task

Each real repository task must pin:

- repository URL
- commit SHA
- license
- language
- setup command
- test command
- timeout
- task description
- expected behavior

> [!IMPORTANT]
> Do not modify upstream repositories. Clone or copy into isolated benchmark workspaces.

## ✅ Review Checklist

| Check | Requirement |
|:---:|---|
| ✅ | Raw JSON output is generated by execution. |
| ✅ | Missing values are `null`. |
| ✅ | The task can run without proprietary services. |
| ✅ | The task has a bounded timeout. |
| ✅ | Control and Aether conditions are comparable. |
| ✅ | Documentation avoids universal claims. |
